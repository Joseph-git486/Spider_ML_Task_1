# RAGe — Retrieval-Augmented Generation Chat Interface

A conversational research assistant that answers questions using content from academic papers. Built with a custom Flask backend and vanilla JS frontend — no Streamlit.

---

## What it does

RAGe lets you query a collection of research PDFs through a chat interface. It retrieves the most relevant chunks from the papers using semantic search, then passes them as context to an LLM to generate a grounded answer — citing the source paper(s) it used.

---

## Tech Stack

| Layer | Tool |
|---|---|
| Embedding model | `sentence-transformers` (all-MiniLM-L6-v2) |
| Vector database | `ChromaDB` (cosine similarity, persistent) |
| LLM | `Groq API` — LLaMA 3.3 70B Versatile |
| Backend | `Flask` + `flask-cors` |
| PDF parsing | `PyMuPDF (fitz)` |
| Frontend | Vanilla HTML, CSS, JavaScript |

## Setup

### 1. Install dependencies

```bash
pip install flask flask-cors chromadb sentence-transformers groq pymupdf python-dotenv
```

### 2. Add your API key

Create a `.env` file in the project root:

```
GROQ_API_KEY=your_key_here
```

### 3. Add your PDFs

Place your research PDF files inside the `RAG_PDFs/` folder.

### 4. Run ingestion

```bash
python ingestion.py
```

This parses the PDFs, chunks the text, generates embeddings, and stores everything in `chroma_db/`.

> If you want to re-ingest, delete the `chroma_db/` folder first.

### 5. Start the server

```bash
python app.py
```

Open `http://127.0.0.1:5000` in your browser.

## How it works

1. **Ingestion** — PDFs are parsed with PyMuPDF. The References section is stripped. Text is split into overlapping chunks (1000 chars, 200 char overlap). Chunks are embedded with `all-MiniLM-L6-v2` and stored in ChromaDB.

2. **Retrieval** — On each query, the question is embedded and the top-5 most similar chunks are fetched from ChromaDB using cosine similarity.

3. **Generation** — The retrieved chunks are passed as context to LLaMA 3.3 70B via Groq. The model is instructed to answer only from the provided context and cite the source paper.

4. **Frontend** — The chat UI sends queries to `/ask` via `fetch`, displays user and LLM messages as styled bubbles, and auto-scrolls to the latest message.
